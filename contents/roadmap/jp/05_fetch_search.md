# Experiment：Search で発見し、Fetch で根拠を読む

このカードは Anomalo の `Search & Fetch` Web 検索能力を記録するもので、花見 CLI を単純に拡張したものではない。実装では `web_search` → `web_fetch` の順に二つを呼び出す。前者が候補ソースを見つけ、後者が選んだページを読み、Agent が扱える Markdown を返す。

## 検証課題

Agent は関連しそうなソースを探し、その本文を読みながらソースの境界を保つ必要がある。一つの「Web ツール」だけでは発見、根拠の取得、失敗理由が混ざるため、この経路を観測可能で制約できる二段階に分けられるかを検証した。

## 方法

`web_search` は DuckDuckGo HTML を使い、タイトル、URL、スニペットを返す。同じクエリには短期キャッシュを使う。`web_fetch` は公開 HTTP(S) のみを受け付け、direct モードでは HTML を Markdown に変換し、文字範囲と続きのオフセットを扱う。`auto` モードで JavaScript 依存らしいページを検出すると、FruitSpy の Crawl4AI エンドポイントへ渡す。呼び出し、プロバイダー、処理時間は現在のセッションの Web Activity trace に記録される。

## 結果

実装とテストでは、構造化された検索結果、検索キャッシュ、直接ページ変換、動的ページのフォールバック、プライベートアドレスとクロスオリジンの認証リダイレクトの拒否を確認している。Agent が受け取るのは候補ソースと読みやすい本文であり、検索、生成、引用を混ぜたブラックボックスの回答ではない。

## 制約

検索は DuckDuckGo HTML に依存するため、チャレンジやレート制限を受ける可能性がある。Fetch は公開アドレスに限られ、動的ページのフォールバックには FruitSpy Crawl4AI の設定が必要だ。この二つはソースの信頼性を判断したり、最終結論を生成したりしない。ソースの質と根拠の解釈は上位の Agent が担う。

## その後への影響

この検証により、「ネットワーク接続」は独立してテストできる二つの Harness 能力になった。花見 CLI との関係はコードの再利用ではなく経験の連続である。花見が Agent と外部ツールの初期経路を探り、Search & Fetch は Anomalo の公開 Web ソース向けの汎用的な組み合わせになった。
