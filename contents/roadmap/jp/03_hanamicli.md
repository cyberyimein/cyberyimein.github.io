# 実験：Hanami CLI で Agent の直接ツール呼び出しを検証する

Hanami CLI は、桜の予想開花日を取得し、表示ページを更新する小さな実験である。従来型の CLI と Agent Skill を組み合わせ、すべての処理を MCP Server で包む前に、具体的なワークフローで Agent が直接ツールを呼び出せるかを検証する。公開資料に記録されているのは、ローカルの OpenClaw 環境でのテストだけである。

## 検証課題

Agent にツールを公開する二つの方法を比較する。一つは Skill で説明した CLI を Agent が直接呼び出す方法、もう一つは MCP 経由でツールを呼び出す方法である。すべての場面で CLI が MCP を置き換えられるかではなく、単純な季節データ取得に軽いインターフェースを使えるかを問う。

## 方法

CLI が天気予報サイトから桜の予想開花日を取得し、簡単な表示ページへ同期する。Skill は呼び出しの境界と使い方を記述し、ローカル Agent が CLI を発見して実行できるようにする。実装リポジトリと具体的なインターフェースは公開されていないため、記録されていない取得方式、ページ構造、テストデータは追加しない。

## 結果

記録された結果は、ローカルの OpenClaw 環境でこのワークフローが動作したことだ。CLI と Skill の組み合わせがこの限定されたワークフローで実行可能だとは言えるが、複雑なオーケストレーション、権限管理、プロトコル互換性、別の Agent 環境で MCP を置き換えられることまでは示さない。

## 制約

公開コードリポジトリ、実行ログ、テストサンプル、MCP との比較指標は確認できない。そのため、取得の安定性、季節データの更新方針、失敗処理、長期的な保守コストは未検証である。

## その後への影響

このロードマップカードは完了として扱っている。公開記録には次の実装が記載されていない。確認できる結論は、従来型 CLI と Skill によって、この具体的な処理をローカルの OpenClaw 環境で実行できたことに限られる。
