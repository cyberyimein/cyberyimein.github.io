# Experiment：Agent に部屋の環境を読ませる

この実験では、Anomalo が新しい MCP プロトコルへ接続する経路を検証した。FruitSpy が公開する室内環境 MCP Server を通じて、Agent は私の部屋の温度、湿度、二酸化炭素濃度を取得できる。現在の結論は、プロトコル接続と構造化ツール呼び出しは動作するが、まだ連続環境モニタリングシステムではないということだ。

## 検証課題

MCP は抽象的なソフトウェアサービスだけでなく、明確な境界の中で実環境の状態にも接続できるべきだ。新しいステートレスプロトコルでリモートの Streamable HTTP Server に接続し、室内環境ツールを発見して、センサー結果を Agent に渡せるかを検証した。

## 方法

Anomalo では `fruitspy_room_climate` を `streamable_http` として設定し、プロトコルモードを `auto` にして、FruitSpy の `/api/v1/tools/room-climate/mcp` エンドポイントを指定する。MCP Provider はまず `server/discover` を探り、必要なら旧 `initialize` ハンドシェイクへフォールバックする。ツールを発見した後、`get_room_climate` を呼び出して構造化された内容を取得する。設定とリモートアドレスは信頼ネットワーク向けであり、サーバーはセッション単位で有効化する。

## 結果

実際の検証では、Agent に部屋の温度、湿度、二酸化炭素濃度を正常に読み取らせた。Anomalo のテストでも、リモートツールの発見、構造化された `temperature_c`、リクエストメタデータ、`2026-07-28` の現行プロトコル表示を確認し、`2025-11-25` のレガシーフォールバック認識も残している。これは Agent から MCP Server までの呼び出し経路を確認したものであり、センサー校正の報告ではない。

## 制約

現在の設定は信頼できる LAN を対象とし、FruitSpy サービスとオンラインのセンサーに依存する。この検証は現在値を取得できることを記録しただけで、連続サンプリング、履歴保存、閾値アラート、センサー精度を示すものではない。テストが主に検証するのは物理デバイスではなく MCP アダプターである。

## その後への影響

環境センシングによって、Harness はソフトウェアツールから部屋の物理状態へ拡張され、MCP 分岐に観測可能な実入力が加わった。次は繰り返し読み取り、サービス停止、壊れたデータへの挙動を記録し、環境コンテキストを Agent の長期記憶や自動化ルールに入れるかを決める。
