# Kabumemo：由 Agent 持续演进的个人交易日志

Kabumemo 是一个离线优先的个人股票交易日志，用于管理成交、持仓、资金、税务和券商报表。它从周末完成的 CRUD 工具开始，经过多轮 Agent 重构，现在由 Vue 3 前端、FastAPI 后端和本地双存储组成。

## 背景与目标

我最初使用 Notion 记录交易，但通用表格无法自然表达资金组、多币种结算和纳税状态。与其继续调整数据去适应工具，我选择按自己的交易流程建立数据模型。

这个项目也用于观察 Agent 能否长期维护真实软件。我负责提出需求和 Review，Agent 负责实现与重构。关注点不是一次生成多少代码，而是它能否理解已有领域模型，在不破坏真实数据的前提下持续修改前端、后端和部署方式。

## 设计与实现

前端使用 Vue 3、TypeScript 和 Vite，默认从券商报表中心进入，也保留手工交易录入作为纠错入口。FastAPI 后端集中处理交易校验、持仓与收益计算、资金流水、税务和数据导入，并通过 Pydantic 约束接口数据。

券商报表采用“预览、应用、撤销”的导入流程，支持日股成交、美股成交、日元出入金和外币出入金。系统使用稳定业务 ID 跳过重复记录，并识别成交与资金流水之间的联动关系。

JSON 文件仍是便于检查和恢复的主数据源。每次写入会同步镜像到 SQLite；配套脚本可以检查两边是否一致，也可以从 JSON 或券商 CSV 重建结构化数据。

## 当前能力

- 记录和编辑交易，按币种、资金组和账户类型计算持仓与已实现损益。
- 从券商报表导入成交和资金流水，预览重复项，并撤销一次导入。
- 管理资金组、追加资金、外汇兑换、逐笔税务结算和年度税务结算。
- 处理拆股记录，并在持仓与已实现损益计算中应用调整。
- 查看一年价格历史、买卖点和一轮交易的毛利、净利、税务影响与年化收益。
- 检测可疑重复交易并批量删除，使用 pytest 与 Vue 类型检查保护关键数据流程。

## 边界与取舍

Kabumemo 面向个人工作流，不是通用券商或多人投资平台。当前数据模型重点覆盖 JPY、USD 和现有券商报表；手工录入主要用于修正或补充自动导入结果。

双存储的目的不是维护两个独立事实来源。JSON 保持可读和可恢复，SQLite 用于结构化查询与外部工具；同步检查用于发现两者之间的漂移。

## 状态与下一步

Kabumemo 仍在活跃开发。生产版本会把 Vue 前端和 FastAPI 后端构建为同一个 OCI 镜像，并通过 Apple Container 运行在 Mac mini 上；数据目录从宿主机挂载，替换容器不会删除交易记录。

下一阶段将继续完善备份与恢复、筛选和导出，并扩大多币种、跨资金组及券商报表边界条件的测试覆盖。

## 技术栈

Vue 3 / TypeScript / Vite / FastAPI / Pydantic / JSON / SQLite / ECharts / pytest / Apple Container
