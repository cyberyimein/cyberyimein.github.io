# Urus：米国株リサーチを再検証可能なワークフローにする

Urus は、米国株と ETF を対象とするリサーチ・意思決定支援システムである。市場・マクロデータ、テクニカル指標と相対強度、オプション構造、リサーチレポート、任意の Agent 分析を、実行状態と証拠を明示する一つのワークフローにまとめる。現行バージョンは 0.1.0 で開発中であり、ライブデータソースと Agent は既定で無効になっている。証券会社への発注も行わない。

## 背景と目標

株式リサーチでは、市場環境、マクロ要因、オプション構造、銘柄間の比較を組み合わせて判断することが多い。難しいのはデータソースの数だけではない。各実行について、どのデータを使ったか、どのステップをスキップしたか、どの出力がプレースホルダーだったかを後から確認できる必要がある。

Urus は、マーケット収集、マクロイベント要約、オプション収集、銘柄収集、企業イベント要約、意思決定分析、出力という七つの交換可能なステップから始めている。目的は単一の指標を売買指示へ変換することではない。各実行の入力スナップショット、データ品質、モデル出力、ツールトレースを保存し、後続のリサーチや Agent 分析が凍結された証拠を基に動けるようにすることである。

## 設計と実装

Urus は一つの FastAPI バックエンドと一つの Vue 3 フロントエンドで構成する。両者は独立して起動・デプロイできる。バックエンドの永続化には SQLAlchemy と Alembic を使い、フロントエンドは集中管理した API client 経由で読み取る。データベースや外部マーケットサービスへ直接アクセスすることはない。

各実行は `Run`、`StepRun`、`Snapshot` を記録する。フロントエンドは小さな read model を読み取り、オプションチェーン、銘柄の日足、テクニカル入力は正規化した SQLite テーブルへ snapshot と同じトランザクションで保存する。これにより表示を軽く保ちながら、後の再計算と検証に必要な境界を残せる。

ライブデータは明示的な adapter 経由で接続する。Moomoo OpenD は ETF と株式のスナップショットおよび日足をまとめて取得し、Yahoo Finance と FRED は日次のマクロコンテキストを提供する。OpenD は開発 LAN 上の別ホストで動かせるが、アドレスはローカルまたはデプロイ環境の設定だけに置く。

Stage 4B の Agent にオープンなデータベースインターフェースは渡さない。まず、ペアになったスナップショットを、ソースハッシュ、変化、品質警告、実行制限を含む decision packet に圧縮する。その後 `urus-equity-decision` と `urus-options-decision` が限定されたリサーチタスクを処理する。OpenRouter を有効にした場合も、モデルが使えるのは読み取り専用のデータ・数学ツールだけであり、意思決定、モデルターン、ツールトレースは SQLite に保存する。

## 現在の機能

- Stage 1A は ETF の一括スナップショット、QQQ の日足テクニカル指標、Yahoo Finance と FRED の日次マクロデータに対応する。
- Moomoo を有効にすると、Stage 2 はオプションチェーンを収集し、DEX、GEX、Gamma Wall、Max Pain、Expected Move、Spot Gamma Profile、Gamma Flip を計算する。
- Stage 3A は QQQ をベンチマークとして、設定された主要 ETF と公開ウォッチリストを収集し、リターン、移動平均、ボラティリティ、ATR、ボリンジャーバンド、MACD、出来高シグナル、相対リターン、ベータ、相関を計算する。
- フロントエンドには Dashboard、Runs、実行詳細、リサーチレポートの画面があり、通常取引価格、プレマーケット価格、アフターマーケット価格を分けて表示する。
- 定期収集スクリプトは `exchange-calendars` で取引日、休日、早仕舞いを扱い、既定では AI の意思決定を実行しない。
- Stage 4B は任意の decision packet、株式ランキング、オプション構造の解釈、監査記録を提供する。ライブデータまたは Agent が無効な場合も、`disabled`、`unavailable`、`placeholder`、`partial`、`skipped` などの状態を保持する。

## 境界とトレードオフ

現時点の Urus にはログイン、認可、マルチテナント分離、Sentry、Prometheus、完全なコンテナオーケストレーションがない。公開インターネットへ直接公開する用途には適さない。証券会社の発注接続、自動売買、投資助言も提供しない。

オプション構造はモデルの出力であり、既知のマーケットメイカーのネットポジションではない。現在の Gamma 計算は、明示的に設定した無リスク金利、配当率、現値レンジ、点数と、Call を正、Put を負とするポジション方向の仮定を使う。動的金利、動的配当、正確な 0DTE 残存時間、VEX/Vanna、ティック単位のオプション履歴は今後の精度向上項目である。

マクロイベントと企業イベントの要約は条件付きステップとして残っている。関連イベントがなければ 1B と 3B は通常どおりスキップする。全体の実行状態が `mixed` でも、完了したデータ収集が失敗したことを意味しない。後続ステップが `skipped` または `placeholder` の場合にもこの状態になる。

## 状態と次のステップ

Urus はバージョン 0.1.0 の開発中プロジェクトである。Stage 1A、オプション構造の永続化、Stage 3A は同じワークフローとフロントエンドに接続されている。現行 checkout では、バックエンドの pytest、フロントエンドの Vitest、プロダクションビルドがすべて通過している。

次のステップは、3B の企業イベントと財務要約を実装し、セクターベンチマークとウォッチリストを広げ、長期履歴アーカイブと動的な金利・配当モデルを段階的に追加することである。信頼できるネットワークの外へデプロイするには、認証とアクセス制御が前提となる。
