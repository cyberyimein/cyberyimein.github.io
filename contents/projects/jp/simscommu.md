# SimsCommu：音声練習フローを検証するマルチ Agent アプリケーション

SimsCommu は、v0.2.0 のマルチ Agent 会話練習 Web アプリである。シナリオ設定、役割ルーティング、リモート STT、テキスト LLM、リモート TTS を実行可能な練習フローへつないでいる。現在の結論は、STT → TTT → TTS の直列構成はフロー検証には使えるが、再始動時の技術基盤にはしないというものだ。

## 背景と目標

音声で始まり音声で終わる練習アプリを作り、具体的な構成を検証したかった。STT が音声をテキストへ変換し、TTT が理解と生成を担当し、TTS が返答を音声へ変換する。会話練習にはシナリオ内の複数の役割も必要なため、マルチ Agent の役割オーケストレーションも検証対象にした。

## 設計と実装

メインアプリは Fastify と TypeScript で API を提供し、React と Vite でフロントエンドを構成する。ユーザーが言語、シナリオ、ユーザー役、Agent 数を設定すると、OpenRouter で役割設定を生成してセッションを作成する。

各ユーザーターンでは、最初にホスト Agent が動く。シナリオ、ユーザー役、利用可能な役割、会話履歴から次に返答する役割を選び、ルーティング理由を返す。その後、選ばれた役割 Agent が返答を生成する。セッション履歴はメインプロセスのメモリに保持し、直近 40 メッセージに制限する。ルーティングと返答のイベントは WebSocket で送る。

フロントエンドが音声を録音し、メインアプリが独立した STT サービスへ転送する。返答テキストは独立した TTS サービスへ送る。現在の経路は直列であり、音声入力が終わってからテキスト処理と音声出力が始まる。

## 現在の機能

- 言語、シナリオ、ユーザー役、Agent 数から練習設定を生成する。
- ホスト Agent が複数の役割から次の返答者を選ぶ。
- セッションを作成し、履歴を制限して保持し、ルーティングと返答イベントを WebSocket で配信する。
- 録音をリモート STT サービスへ送り、返答をリモート TTS サービスへ送る。
- シナリオ、モジュール、Prompt ID によって OpenRouter のモデルを振り分ける。
- Fastify バックエンドと React フロントエンドの開発・本番ビルド確認を提供する。

## 境界とトレードオフ

現在の実装は、リモート STT、リモート TTS、OpenRouter の設定に依存する。セッション状態はプロセスのメモリにあり、再起動後へは保存されない。音声経路も Live 双方向ではないため、同じターンでユーザーと Agent が自然に割り込むことはできない。

これは会話練習の実験であり、汎用的なカスタマーサービスシステムではない。ルーティング結果を客観的な評価として扱うこともない。ホストと役割の返答はモデル呼び出しから生成されるため、品質は Prompt、モデル、リモートサービスの状態に左右される。

## 状態と次のステップ

SimsCommu は現在中止しており、再始動を待っている。現在の実装と直列構成から得た結果は残すが、この経路を拡張する予定はない。次は Live 双方向モデルを中心に音声経路を再設計し、ホスト Agent、役割オーケストレーション、練習フィードバックをリアルタイムセッションへどう組み込むかを改めて検討する。
