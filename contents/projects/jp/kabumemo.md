# Kabumemo：Agent と継続的に育てる個人取引ジャーナル

Kabumemo は、取引、保有、資金、税務、証券会社のレポートを管理するオフライン優先の個人向け株式取引ジャーナルである。週末に作った CRUD ツールから始まり、複数回の Agent によるリファクタリングを経て、現在は Vue 3 フロントエンド、FastAPI バックエンド、ローカル二重保存で構成している。

## 背景と目標

当初は Notion で取引を記録していたが、汎用的な表では資金グループ、複数通貨での決済、納税状態を自然に表現できなかった。データをツールに合わせ続ける代わりに、自分の取引フローを基準としたデータモデルを作ることにした。

このプロジェクトでは、Agent が実際のソフトウェアを長期的に保守できるかも検証している。私が要件を定義して結果をレビューし、Agent が実装とリファクタリングを担当する。一度に生成できるコード量ではなく、既存のドメインモデルを理解し、実データを壊さずにフロントエンド、バックエンド、デプロイ方法を変更できるかを重視している。

## 設計と実装

フロントエンドは Vue 3、TypeScript、Vite を使用する。初期画面は証券会社レポートの管理画面であり、修正用として手動の取引入力も残している。FastAPI バックエンドは取引の検証、保有と収益の計算、資金移動、税務、データ取り込みを処理し、Pydantic で API データを制約する。

証券会社レポートは、プレビュー、適用、取り消しの順に取り込む。国内株式、米国株式、円貨入出金、外貨入出金のレポートに対応する。安定した業務 ID で重複を除外し、関連する取引と資金移動を紐付ける。

JSON ファイルは、内容を確認しやすく復旧可能な主データとして維持する。各書き込みは SQLite にも同期する。保守スクリプトで両方の整合性を確認し、JSON または証券会社の CSV から構造化データを再構築できる。

## 現在の機能

- 取引を記録・編集し、通貨、資金グループ、口座種別ごとに保有と実現損益を計算する。
- 証券会社レポートから取引と資金移動を取り込み、重複を事前確認し、一回の取り込みを取り消す。
- 資金グループ、追加資金、外貨交換、取引単位の納税、年間納税を管理する。
- 株式分割を記録し、保有と実現損益の計算に調整を反映する。
- 1 年分の価格履歴と売買点、一往復取引の粗利益、純利益、税務影響、年率換算リターンを表示する。
- 疑わしい重複取引を確認して一括削除し、pytest と Vue の型チェックで重要なデータフローを保護する。

## 境界とトレードオフ

Kabumemo は個人のワークフロー向けであり、汎用的な証券システムや複数ユーザー向け投資プラットフォームではない。現在のデータモデルは JPY、USD、対応済みの証券会社レポートを中心とする。手動入力は主に、取り込んだデータの修正や補足に使用する。

二重保存は、独立した二つの正本を維持するためのものではない。JSON は可読性と復旧性を担い、SQLite は構造化クエリと外部ツール連携に使用する。整合性チェックで両者の差異を検出する。

## 状態と次のステップ

Kabumemo は現在も開発中である。本番環境では Vue フロントエンドと FastAPI バックエンドを一つの OCI イメージにまとめ、Mac mini 上の Apple Container で実行する。データディレクトリはホストからマウントするため、コンテナを置き換えても取引記録は削除されない。

次の段階では、バックアップと復元、フィルタリング、エクスポートを改善し、複数通貨、資金グループ間処理、証券会社レポートの境界条件に対するテストを拡充する。
